# Help and voluntary support

## Get help

Start with [getting started](docs/getting-started.md),
[compatibility](docs/compatibility.md) and [troubleshooting](docs/troubleshooting.md).
Use the repository's [issue tracker](https://github.com/blackcancer/VBAi/issues)
for reproducible defects and feature proposals. Use the host-compatibility template
when testing an application or a VBE configuration not yet covered by the evidence.

Include your VBAi build or commit, host and VBE versions, process architecture,
Windows version, UI language, relevant provider, reproduction steps and the actual
result. The About window can copy technical details. Review that text and any
attachments before posting; replace business documents with a minimal example.

For confidential contact, email **init-sys-rev@hotmail.com**. Vulnerabilities must
follow the [security policy](SECURITY.md), not the public issue route. Support is
best-effort; there is no service-level agreement or guaranteed response time.

## Support the project

Using the software, reporting a precise bug, contributing a fix, improving a
translation or documenting a host test are all useful ways to help.

Financial support, when offered through an official link published by the
maintainer, is a **voluntary contribution**. It does not unlock functionality,
purchase priority support or impose a delivery schedule. No payment destination
is configured in this documentation; do not infer one from a username or an
unofficial page.

Provider subscriptions and API usage charges are separate from donations to VBAi.
